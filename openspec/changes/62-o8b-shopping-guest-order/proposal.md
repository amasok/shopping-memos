# Proposal: ゲストのリストとリストの商品の並びをログイン中にそろえる（#62 O8 の保留分）

Issue: #62（https://github.com/amasok/shopping-memos/issues/62）の O8 から分けたもの

**状態: 承認済み（2026-11-18、ユーザーが提案どおりで承認）**。ユーザーの不在中に、判断が要る部分を `62-o8-shopping-local-first` から分けた（リーダーの指示、2026-11-17）。`62-o8-shopping-local-first` が archive されてから実装する（この change の specs は、それが作る `openspec/specs/shopping` の Requirement を変える）。`62-o7b-catalog-guest-alignment`（商品・タグの並び）と同じ判断なので、まとめて答えてもらうとよい。

## Why

O8 で、ゲストとローカルファーストの買い物の読み取りを同じ関数（`shoppingQueries.ts`）にしたが、並びはモードごとに今のまま残した。ログイン中（サーバー）はリストとリストの商品を作成日時の古い順に出し、ゲストは並べ替えない（ID の順で、作った順とは関係がない）。そろえると、ゲストの画面の並びが変わる。

## What Changes

- ゲストのリストの一覧とリストの商品の並びを、ログイン中と同じ作成日時の古い順にする（提案）

## Capabilities

### New Capabilities

なし

### Modified Capabilities

- `shopping`: 「端末の DB の買い物の一覧」の並びを、モードによらず作成日時の古い順にする

## 影響するモード

| モード | 影響 |
|-------|------|
| ゲスト | ホームのリストの一覧・リストの詳細の商品の並びが、作った順（古い順）になる |
| サーバーファースト・ローカルファースト | 変わらない |

## Non-goals

- 履歴の並び（どのモードも購入日時の新しい順で、すでに同じ）
- サーバーの並びの変更

## Impact

- 変更: `src/hooks/data/shoppingQueries.ts`（`order` の分岐をなくす）。並びに頼る E2E があれば直す

## ユーザーに確認すること

承認済み（2026-11-18、ユーザーが提案どおりで承認）。

1. **ゲストのリストとリストの商品の並び**: 今は、ログイン中は作成日時の古い順、ゲストは並べ替えなし（作った順と関係のない ID の順）。ログイン中に合わせてよいか
   - 提案: 合わせる（ゲストは作った順に並ぶようになる。今のゲストの並びは作った順になっていないので、使い勝手は良くなるはず）
