# Proposal: メニューの「リストを削除」で商品ごと消す選択を削除に使う

Issue: #191（https://github.com/amasok/shopping-memos/issues/191）

**状態: 承認済み（承認: 2026-11-18、リーダー（ユーザーから委任））。実装済み（tester: E2E 全部 chromium 72・Mobile Chrome 72・chromium-auth 51・offline 13（4 skipped）で失敗 0、reviewer: LGTM）**。ユーザーは 2026-11-18 に「直す、仕様とかはそちらで決めていいよ」と答え、仕様の承認をリーダーに委ねた。

## Why

買い物リストの詳細のメニューの「リストを削除」のダイアログで「完全に削除する」（アイテムも削除されます）を選んでも、その選択がどこにも使われず、リストだけが消えて商品は「買いたいもの」に残る。179b（#179）で `deleteList` に、リストと同じ名前・同じスコープの未購入の商品も消す指定（`deleteCatalogItems`）が 3 つのモードに入ったので、選択をそこにつなぐ。

## 今のダイアログ（コードから書き起こし）

- タイトル「リストを削除」、本文「このリストを削除しますか？」
- リストに商品があるときだけ「リスト内のアイテム（N件）の扱い」のラジオ
  - 「買いたいものに戻す」（アイテムは削除されません）… 既定
  - 「完全に削除する」（アイテムも削除されます）
- ボタン「キャンセル」「削除する」。「削除する」は選択にかかわらず `deleteList(listId)` を呼び、`/lists` に移る
- 選択はダイアログを閉じても残る（「完全に削除する」を選んでキャンセルし、開き直すとそのまま）。削除の失敗は何も表示しない

## What Changes

- 「削除する」を押すと、選んだ方法を `deleteList(listId, { deleteCatalogItems })` に渡す。消す範囲は 179b の「リストの商品ごと消す」と同じ（リストの商品と同じ名前・同じスコープの、未購入で論理削除されていないカタログの商品）。購入済みの商品と購入履歴は消さない
- 言葉を 179b のチェック 0 件のダイアログにそろえる（下の「決めたこと」）
- ダイアログを開くたびに「リストだけ消して商品は元に戻す」を選んだ状態にする（危ない方の選択を持ち越さない）
- リストに商品がないときは、今のとおり選択を出さず、リストだけを消す
- 削除に失敗したら、ダイアログにエラーを出してリストの画面のままにする（179b のチェック 0 件のダイアログと同じ）。削除の途中はボタンを押せなくする

## 決めたこと（リーダーに委任、2026-11-18）

1. **消す範囲**: 179b の「リストの商品ごと消す」と同じ。サーバー（tRPC）・ゲスト・ローカルファーストで同じ結果になる（179b の「リストと同じ名前の未購入の商品も消すリストの削除」をそのまま使う）
2. **もう一方の選択肢の意味**: カタログの商品は変えず、リストがなくなることで「買いたいもの」の一覧にまた出る（今の動きのまま）
3. **購入済みの商品・購入履歴**: どちらの選択でも消さない
4. **文言**（179b にそろえる。「アイテム」は使わず「商品」）
   - タイトル「リストを削除」、本文「このリストを削除しますか？」（変えない）
   - 見出し: 「リストの商品（N件）はどうしますか？」
   - 選択肢 1（既定）: 「リストだけ消して商品は元に戻す」／説明「買いたいものの一覧に戻ります」
   - 選択肢 2: 「リストの商品ごと消す」／説明「同じ名前のまだ買っていない商品も消します。買った商品と履歴は残ります」
   - ボタン: 「キャンセル」「削除する」（変えない）
   - 失敗のメッセージ: 「リストを削除できませんでした。もう一度お試しください」（179b と同じ）

## Capabilities

### New Capabilities

なし

### Modified Capabilities

- `shopping`: 「メニューからのリストの削除」を足す（画面の選択と、`deleteList` の指定のつなぎ）。`deleteList` の指定そのものの Requirement（179b）は変えない

## 影響するモード

| モード | 影響 |
|-------|------|
| ゲスト（Dexie だけ） | 画面の変更だけ。「リストの商品ごと消す」は端末の DB の `deleteList` の指定（179b）で、同じ groupId の未購入の商品を消す |
| サーバーファースト（tRPC） | 画面の変更だけ。`shopping.deleteList` に `deleteCatalogItems: true` が届く（179b で入った入力） |
| ローカルファースト（`NEXT_PUBLIC_LOCAL_FIRST`） | 画面の変更だけ。端末の DB で消してキューに削除を積む（179b） |

## Non-goals

- `deleteList` の指定の範囲・トランザクション・同期（179b のまま）
- 商品をすべて外したときの「リストが空になりました」のダイアログ
- チェック 0 件の完了のダイアログ（179b のまま）
- ダイアログを 179b と同じボタン 3 つの形にすること（ラジオと「削除する」の形は残す）
- DB・API・Dexie のスキーマの変更（ない）

## Impact

- 変更: `src/app/lists/detail/page.tsx`（ダイアログ）、`src/app/lists/detail/__tests__/page.test.tsx`、`e2e/shopping.spec.ts`（ゲスト）、`e2e/auth/`（ログイン中）
- API・DB の migration: なし
