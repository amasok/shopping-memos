## Purpose

商品（カタログのアイテム）とタグの一覧と、作成・更新・削除を定める。ゲスト（端末の DB だけ）・サーバーファースト（tRPC）・ローカルファースト（端末の DB に書いて同期）のどのモードで、どこを読み書きするかと、一覧の絞り込みの規則を持つ。

## ADDED Requirements

### Requirement: モードによる読み書きの経路

システムは、カタログの読み書きの経路を次のように決めなければならない（MUST）。ログインしていなければ端末のゲスト DB。ログイン中で merge が終わっていて、`NEXT_PUBLIC_LOCAL_FIRST` が `"true"` ならユーザー DB（ローカルファースト）。それ以外のログイン中で merge が終わっていればサーバー（tRPC）。ログイン中で merge が終わる前は、今と同じくゲスト DB。

#### Scenario: ゲストはゲスト DB を読み書きする
- **WHEN** ログインしていない状態で、商品を作って一覧を出す
- **THEN** 商品はゲスト DB に書かれ、一覧はゲスト DB から読まれ、同期のキューには何も積まれない

#### Scenario: フラグが false ならログイン中はサーバーを読み書きする
- **WHEN** フラグが false でログインし merge が終わった状態で、商品を作って一覧を出す
- **THEN** 作成と一覧は tRPC（`catalog.createItem`・`catalog.getItems`）で行い、端末の DB には書かない

#### Scenario: フラグが true ならログイン中はユーザー DB を読み書きする
- **WHEN** フラグが true でログインし merge が終わった状態で、商品を作って一覧を出す
- **THEN** 商品はユーザー DB に書かれ、一覧はユーザー DB から読まれ、tRPC のカタログの API は呼ばない

### Requirement: ローカルファーストの書き込みと同期のキュー

ローカルファーストで商品・タグを作る・変える・消すと、システムは、ユーザー DB の行と同期のキューの操作を 1 つのトランザクションで書き、書き込みの後に同期を予約しなければならない（MUST）。キューの操作は、sync.push が受け付けるフィールドだけを持つ。どちらかの書き込みに失敗したら、どちらも書かない。

#### Scenario: 商品を作ると行とキューの作成の操作が書かれる
- **WHEN** ローカルファーストで、グループ A に名前「牛乳」・数量 2・メモ・タグの商品を作る
- **THEN** ユーザー DB に商品ができ、キューに `create` の操作（name・quantity・memo・tagIds・groupId）が積まれ、同期が予約される

#### Scenario: 商品を変えると変えたフィールドだけがキューに積まれる
- **WHEN** ローカルファーストで、商品の数量だけを変える
- **THEN** ユーザー DB の商品の数量と更新日時が変わり、キューに `update` の操作（quantity だけ）が積まれる

#### Scenario: 商品の更新で送るフィールドは今の tRPC の更新と同じ
- **WHEN** ローカルファーストで、商品の名前・数量・メモ・タグを変え、メモを空（null）にする
- **THEN** キューの `update` のパッチは name・quantity・tagIds と、空でないときの memo だけを持ち（今の tRPC の更新と同じく、メモの null は送らない）、groupId と purchasedAt は持たない

#### Scenario: 商品を消すとキューに削除の操作が積まれる
- **WHEN** ローカルファーストで、商品を消す
- **THEN** ユーザー DB から商品が消え、キューに `delete` の操作が積まれる

#### Scenario: タグを作る・名前を変えるとキューに積まれる
- **WHEN** ローカルファーストで、タグを作り、その名前を変える
- **THEN** ユーザー DB のタグが変わり、キューにはタグの `create` が 1 つだけ（名前の変更がまとめられて）積まれる

#### Scenario: タグを消すと商品のタグからも外し、商品の更新もキューに積む
- **WHEN** ローカルファーストで、送信済みの商品に付いている送信済みのタグを消す
- **THEN** ユーザー DB からタグが消え、その商品の `tagIds` からも外れ、キューにはタグの `delete` と、商品の `update`（tagIds だけ）が積まれる

#### Scenario: 送る前に作ったタグを消すと商品の作成のパッチからも外れる
- **WHEN** ローカルファーストで、オフラインのままタグ X を作り、X を付けた商品を作り、X を消す
- **THEN** キューからタグ X の `create` と `delete` は消え、商品の `create` のパッチの `tagIds` に X は残らない（サーバーで参照の不正として拒否されない）

#### Scenario: キューに積めなければ行も書かない
- **WHEN** ローカルファーストで商品を作るときに、キューへの書き込みが失敗する
- **THEN** ユーザー DB に商品はできず、エラーが返る

### Requirement: ゲストの書き込み

ゲストで商品・タグを作る・変える・消すと、システムは、ゲスト DB だけに書き、同期のキューには積まず、変えた行の更新日時を更新しなければならない（MUST）。タグを消すと、商品の `tagIds` からも外す。

#### Scenario: ゲストで商品を変えると更新日時が変わりキューには積まない
- **WHEN** ゲストで、商品の名前を変える
- **THEN** ゲスト DB の商品の名前と更新日時が変わり、キューは空のまま

#### Scenario: ゲストでタグを消すと商品のタグからも外す
- **WHEN** ゲストで、商品に付いているタグを消す
- **THEN** ゲスト DB からタグが消え、その商品の `tagIds` からも外れる

### Requirement: 商品の一覧の絞り込み

端末の DB（ゲスト・ローカルファースト）から商品の一覧を出すとき、システムは、選んでいるグループ（個人なら groupId なし）の商品だけを出し、購入済みは指定がなければ除き、タグを指定したらどれかのタグが付いた商品だけを出し、同じグループの進行中のリストにある商品と同じ名前の商品を除かなければならない（MUST）。並びは、ローカルファーストではサーバーと同じ作成日時の古い順、ゲストでは今と同じ新しい順にする。

#### Scenario: 選んでいるグループの商品だけを出す
- **WHEN** 個人の商品とグループ A の商品がある端末の DB で、グループ A を選んで一覧を出す
- **THEN** グループ A の商品だけが出る

#### Scenario: 購入済みの商品は指定がなければ出ない
- **WHEN** 未購入と購入済みの商品がある状態で、指定なしで一覧を出し、次に購入済みだけを指定して出す
- **THEN** 最初は未購入だけ、次は購入済みだけが出る

#### Scenario: タグを指定するとどれかのタグが付いた商品だけを出す
- **WHEN** タグ X・タグ Y・タグなしの商品がある状態で、タグ X と Y を指定して一覧を出す
- **THEN** タグ X か Y が付いた商品だけが出る

#### Scenario: 進行中のリストにある商品は一覧に出ない
- **WHEN** 同じグループの進行中のリストに「牛乳」がある状態で一覧を出す
- **THEN** 「牛乳」の商品は出ず、完了したリストにだけある商品は出る

#### Scenario: ローカルファーストの並びはサーバーと同じ作成日時の古い順
- **WHEN** ローカルファーストで、作成日時の違う 3 つの商品の一覧を出す
- **THEN** 作成日時の古い順に並ぶ

### Requirement: タグの一覧

端末の DB からタグの一覧を出すとき、システムは、選んでいるグループのタグだけを出さなければならない（MUST）。並びは、ローカルファーストでは名前の文字コードの順（UTF-16 の比較）にし、ゲストでは今のまま（並べ替えない）にする。サーバーの名前の順は DB の照合順序で決まるので、照合順序が C でなければ違うことがある。

#### Scenario: ローカルファーストのタグは選んでいるグループのものを名前の文字コードの順に出す
- **WHEN** ローカルファーストで、個人のタグ「食品」「日用品」「Banana」「apple」とグループ A のタグがある状態で、個人のタグの一覧を出す
- **THEN** 個人の「Banana」「apple」「日用品」「食品」の順に出て、グループ A のタグは出ない

### Requirement: 初回の同期が終わるまでの一覧

ローカルファーストで、ユーザー DB の初回の同期（全件の pull）が一度も終わっていないとき、システムは、商品とタグの一覧を「読み込み中」にし、空の一覧として表示してはならない（MUST NOT）。

#### Scenario: 初回の同期の前は読み込み中
- **WHEN** ローカルファーストでログインした直後で、ユーザー DB の同期がまだ一度も終わっていない
- **THEN** 商品とタグの一覧は読み込み中になる

#### Scenario: 初回の同期の後はユーザー DB の一覧を出す
- **WHEN** ユーザー DB の初回の同期が終わる
- **THEN** 商品とタグの一覧が、同期で届いた行で表示される

### Requirement: 買い物の変更の後の同期

ローカルファーストで、買い物（tRPC のまま）のリストや履歴を変えたとき、システムは、すぐに同期して、「買いたいもの」の一覧の除外を追いつかせなければならない（MUST）。フラグが false なら、今と同じく `catalog.getItems` のキャッシュを無効にする。

#### Scenario: ローカルファーストでリストに商品を入れると同期する
- **WHEN** ローカルファーストで、tRPC でリストに商品を入れる
- **THEN** 成功の後に同期が走る

#### Scenario: サーバーファーストではカタログのキャッシュを無効にする
- **WHEN** フラグが false で、リストに商品を入れる
- **THEN** 成功の後に `catalog.getItems` のキャッシュが無効になる
