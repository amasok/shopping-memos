## ADDED Requirements

### Requirement: 初回の表示名の設定

システムは、表示名が空のユーザーがログインしたら、表示名の設定の画面に進ませ、表示名を設定するまでほかの画面を使わせてはならない（MUST NOT）。表示名の設定の画面からは、ログアウトもできる。表示名を設定したら、ログインの前にいた画面（なければホーム）に移す。表示名は前後の空白を除いて 1〜50 文字（コードポイントで数える）とし、空白だけのもの、改行・制御文字・Unicode の書式の文字（一般カテゴリ Cf。向きを変える文字やゼロ幅の文字など）を含むものは保存しない。表示名のあるユーザー（既存の Google のユーザーを含む）は、表示名の設定の画面に進ませない。

#### Scenario: 新しいアドレスでログインすると表示名の設定に進む
- **WHEN** 未登録のアドレスでコードを送り、届いたコードでログインする
- **THEN** 表示名の設定の画面が出る

#### Scenario: 表示名を設定するまで、ほかの画面を開いても設定に戻る
- **WHEN** 表示名を設定していないユーザーが、リストや設定の画面を開く
- **THEN** 表示名の設定の画面に戻る

#### Scenario: 表示名を入れると、ログインの前にいた画面に移る
- **WHEN** グループの画面からログインし、表示名の設定の画面で表示名を入れて「はじめる」を押す
- **THEN** グループの画面に移り、そのユーザーの表示名が保存されている

#### Scenario: 表示名のあるユーザーは表示名の設定に進まない
- **WHEN** 表示名のあるユーザー（Google のログインで作られた想定のユーザーを含む）がコードでログインする
- **THEN** 表示名の設定の画面は出ず、ログインの前にいた画面（なければホーム）に移る

#### Scenario: 空白だけの表示名は保存できない
- **WHEN** 表示名に空白だけを入れて保存する
- **THEN** 保存されず、「表示名を入力してください」が出る

#### Scenario: 50 文字を超える表示名は保存できない
- **WHEN** 51 文字の表示名を入れて保存する
- **THEN** 保存されず、「表示名は 50 文字までです」が出る

#### Scenario: 改行や制御文字を含む表示名は保存できない
- **WHEN** 改行を含む表示名を API で保存する
- **THEN** 保存されず、BAD_REQUEST が返る

#### Scenario: 向きを変える文字やゼロ幅の文字を含む表示名は保存できない
- **WHEN** 右から左への書式の文字（U+202E）や、ゼロ幅の空白（U+200B）を含む表示名を API で保存する
- **THEN** 保存されず、BAD_REQUEST が返る

#### Scenario: 表示名の設定の画面からログアウトできる
- **WHEN** 表示名を設定していないユーザーが、表示名の設定の画面で「ログアウト」を押す
- **THEN** ゲストの表示に戻り、ログイン中だけの状態（merge 済みの印・選んでいたグループ）は消えている

### Requirement: 表示名の変更

システムは、ログイン中のユーザーが設定画面から自分の表示名を変えられるようにしなければならない（MUST）。変えられるのは自分の表示名だけで、ほかのユーザーの表示名やほかの項目（メールアドレス・画像）は変えられない。表示名の検証は初回の設定と同じにする。

#### Scenario: 設定画面で表示名を変えるとグループのメンバー一覧に反映される
- **WHEN** 設定画面で表示名を変えてから、所属するグループのメンバー一覧を開く
- **THEN** 変えた表示名が出る

#### Scenario: 他人の表示名は変えられない
- **WHEN** ログイン中のユーザーが、入力に別のユーザーの id（`userId`）を付けて表示名の保存の API を呼ぶ
- **THEN** 変わるのは自分の表示名だけで、別のユーザーの表示名は変わらない（入力の `userId` は使われない）

#### Scenario: ログインしていないと表示名を変えられない
- **WHEN** ログインしていない状態で、表示名の保存の API を呼ぶ
- **THEN** UNAUTHORIZED が返る

### Requirement: 設定画面のアカウント欄

システムは、ログイン中の設定画面に、表示名・メールアドレス・「表示名を変更」・「すべての端末からログアウト」・「ログアウト」を出さなければならない（MUST）。メールアドレスは表示だけで、変更はできない。

#### Scenario: 設定画面に表示名とメールアドレスが出る
- **WHEN** ログイン中に設定画面を開く
- **THEN** そのユーザーの表示名とメールアドレスが出て、メールアドレスを変える操作はない

#### Scenario: 設定画面で表示名を変えられる
- **WHEN** 設定画面で「表示名を変更」を押し、新しい表示名を入れて保存する
- **THEN** 設定画面の表示名が新しい値になる

### Requirement: すべての端末からログアウト

システムは、ログイン中のユーザーが設定画面から「すべての端末からログアウト」を選んだら、確認の後に、この端末を含むそのユーザーのすべてのセッションをすぐ無効にし、この端末をゲストに戻さなければならない（MUST）。

#### Scenario: すべての端末からログアウトの前に確認する
- **WHEN** 設定画面で「すべての端末からログアウト」を押す
- **THEN** 確認のダイアログが出て、「ログアウトする」を押すまでセッションは無効にならない

#### Scenario: すべての端末からログアウトすると、ほかの端末のセッションも使えなくなる
- **WHEN** 2 つの端末で同じユーザーとしてログインしておき、一方の端末で「すべての端末からログアウト」を選ぶ
- **THEN** もう一方の端末のセッションの Cookie で保護された tRPC の手続きを呼ぶと UNAUTHORIZED が返る

#### Scenario: すべての端末からログアウトすると、この端末はゲストに戻る
- **WHEN** 「すべての端末からログアウト」を選ぶ
- **THEN** この端末はゲストの表示に戻り、ログイン中だけの状態（merge 済みの印・選んでいたグループ）は消えている

#### Scenario: すべての端末からログアウトの API は別のオリジンからは 403 になる
- **WHEN** `Origin` が別のサイトのリクエストで、ログイン中のセッションの Cookie を付けて、すべての端末からログアウトの API を POST する
- **THEN** 403 が返り、セッションは無効にならない

## MODIFIED Requirements

### Requirement: 使わない認証の API を閉じる

システムは、認証の API（`/api/auth/*`）のうち、コードの送信（種類がログインのものだけ）・コードでのログイン・セッションの取得・ログアウト・すべての端末からログアウトだけを受け付け、それ以外のパス（パスワードでの登録・ログイン、ソーシャルログイン、メールの確認、パスワードの再設定、コードの確認だけをする API、ユーザーの更新など）には 404 を返さなければならない（MUST）。受け付けるパスは許可リストで決め、ライブラリが新しいパスを足しても自動では開かない。後の変更（パスキー）は、その変更で許可リストに足す。表示名の保存は認証の API ではなく、アプリの API（tRPC）で行う。

#### Scenario: 許可していないパスは 404 になる
- **WHEN** `/api/auth/sign-up/email`・`/api/auth/sign-in/email`・`/api/auth/sign-in/social`・`/api/auth/email-otp/check-verification-otp`・`/api/auth/email-otp/verify-email`・`/api/auth/forget-password/email-otp`・`/api/auth/email-otp/reset-password`・`/api/auth/update-user` のそれぞれに POST する
- **THEN** どれも 404 が返り、メールは送られず、ユーザーもセッションも作られず、ユーザーの情報も変わらない

#### Scenario: ログイン以外の種類のコードの送信は断る
- **WHEN** コードの送信に、種類としてメールの確認やパスワードの再設定を指定する
- **THEN** 送信は断られ、メールは送られない

#### Scenario: 許可したパスは動く
- **WHEN** コードの送信・コードでのログイン・セッションの取得・ログアウト・すべての端末からログアウトを、アプリの画面から順に呼ぶ
- **THEN** どれも処理される
