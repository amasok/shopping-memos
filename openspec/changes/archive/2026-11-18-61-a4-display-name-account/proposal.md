# Proposal: 初回の表示名の設定と、設定画面のアカウント欄

Issue: #61（https://github.com/amasok/shopping-memos/issues/61）

**状態: 承認済み（2026-11-18）**。ユーザーが末尾の「ユーザーに決めてほしいこと」の 6 点を、すべて提案どおりで承認した（回答「提案どおり承認」。表示名の文字数は 50 のまま）

## Why

A3（`61-a3-email-otp-login`・`61-a3b-otp-abuse-escalation`）で、メールのコードでログインすると、新しいユーザーは表示名が空（`''`）で作られる。グループのメンバー一覧には表示名が出るので、空のままだと家族のだれかが分からない。設計書（`docs/features/passkey-email-auth.md`）の決定事項 5（2026-11-16 ユーザー承認）どおり、初回のログインで表示名を必須にする。あわせて、乗っ取りを疑ったときの最低限の対処として「すべての端末からログアウト」を設定画面に置く（設計書「### 6. セッション」、#73-8）。

## What Changes

- 表示名が空のユーザーがログインすると、表示名の設定の画面（`/onboarding`）に進む。設定するまで、ほかの画面を開いても設定の画面に戻る。設定したら、ログインの前にいた画面（なければホーム）に移る。設定の画面には「ログアウト」も置く（まちがったアドレスでログインした人や、共有の端末で始めた人が抜けられるように）
- 表示名は 1〜50 文字（前後の空白を除き、コードポイントで数える）。空白だけのもの、改行・制御文字・Unicode の書式の文字（向きを変える文字やゼロ幅の文字など）を含むものは受け付けない
- 設定画面のアカウント欄に、表示名・メールアドレス・「表示名を変更」・「すべての端末からログアウト」・「ログアウト」を置く。メールアドレスは表示だけ（変更は対象外）
- 「すべての端末からログアウト」は、この端末を含むそのユーザーのすべてのセッションを無効にし、この端末はゲストに戻る
- 認証の API の許可リストに、すべての端末からログアウトの API（`POST /api/auth/revoke-sessions`）を足す。表示名の保存は tRPC（`identity.updateProfile`）で行い、Better Auth のユーザーの更新の API は開かない

## Capabilities

### New Capabilities

なし

### Modified Capabilities

- `auth`: 「初回の表示名の設定」「表示名の変更」「設定画面のアカウント欄」「すべての端末からログアウト」を足し、「使わない認証の API を閉じる」の許可リストに、すべての端末からログアウトを足す

## 影響するモード

ログイン中（サーバーファースト・ローカルファースト）だけ。ゲストには表示名の設定の画面もアカウント欄も出ない（ゲストの設定画面は今のまま）。

## Non-goals

- パスキー（登録・ログイン・管理、登録の提案）（A5）
- メールアドレスの変更
- アバターの画像（Google のアバターは表示しない。`users.image` は A6 で消す）
- 表示名の重複の確認（同じ表示名の家族がいてもよい）

## Impact

- 依存: A3（`61-a3-email-otp-login`・`61-a3b-otp-abuse-escalation`）。PR は A3b の上に積む
- 変更: `src/shared/schemas`（表示名の検証）、`src/infrastructure/trpc/routers/identity.ts`（`updateProfile`）、`src/infrastructure/auth/route.ts`（許可リスト）、`src/contexts/AuthContext.tsx`、`src/app/onboarding/page.tsx`（新規）、表示名の設定へ誘導する部品、`src/app/settings/page.tsx`、E2E のログインのヘルパー（ログインの後に表示名を入れる）
- DB の migration: なし（`users.name` は A2 で NULL を `''` にしてある。NOT NULL は A6）

## ユーザーに決めてほしいこと（提案つき。2026-11-18 にすべて提案どおりで承認）

1. **表示名を必須にするか**: 提案は「必須（スキップできない）」。設計書の決定事項 5（2026-11-16）のとおり
2. **表示名の文字数**: 提案は「1〜50 文字」（設計書のテスト計画どおり）。グループのメンバー一覧の 1 行に収めたいなら 20 文字も考えられる
3. **設定画面で変えられる項目**: 提案は「表示名だけ」。メールアドレスは表示だけにする（変更は設計書で対象外）
4. **「すべての端末からログアウト」でこの端末もログアウトするか**: 提案は「する」（Better Auth の `revokeSessions` は全部のセッションを消す。この端末だけ残すと、乗っ取られた端末と区別できない）。押す前に確認のダイアログを出す
5. **文言**（提案）
   - 表示名の設定の画面: 見出し「表示名を決めてください」、説明「グループのメンバー一覧に表示されます。あとから設定で変えられます」、ボタン「はじめる」、下に「ログアウト」
   - 入力のエラー: 「表示名を入力してください」（空）、「表示名は 50 文字までです」（長すぎる）、「使えない文字が含まれています」（改行・制御文字・書式の文字）
   - 設定画面: 「表示名を変更」、「すべての端末からログアウト」。確認のダイアログ「すべての端末からログアウトしますか？この端末も含めて、もう一度メールのコードでログインが必要になります」・ボタン「ログアウトする」
6. **既存の Google のユーザーで表示名が空の人**: 提案は「ほかの新しいユーザーと同じく、次のログインで表示名の設定に進む」（A2 で NULL を `''` にした行。本番の家族は Google の名前があるので、通常は出ない）
