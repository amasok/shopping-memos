# Proposal: ゲストとログイン中のカタログの見え方をそろえる（#62 O7 の保留分）

Issue: #62（https://github.com/amasok/shopping-memos/issues/62）の O7 から分けたもの

**状態: 保留（ユーザーの確認待ち）**。ユーザーの不在中に、判断が要る部分を `62-o7-catalog-local-first` から分けた（リーダーの指示、2026-11-17）。下の「ユーザーに確認すること」の答えが出るまで実装しない。`62-o7-catalog-local-first` が archive されてから実装する（この change の specs は、それが作る `openspec/specs/catalog` の Requirement を変える）。

## Why

O7 で、ゲストとローカルファーストのカタログの読み取りを同じ関数（`catalogQueries.ts`）にしたが、並びはモードごとに今のまま残した。ゲストとログイン中で一覧の並びが違う（config の「ゲストとログイン中で結果が同じになるようにする」に反する）。また、`app/items/new/page.tsx` はログインの状態を見ずにゲスト DB に直接書いていて、hooks を通らない（design-doc 7.7）。どちらも、直すと画面の見え方が変わるので、ユーザーに決めてもらう。

## What Changes

- ゲストの一覧の並びを、ログイン中（サーバー）と同じにする（提案。確認事項 1）
  - 商品: ゲストは作成日時の新しい順 → 古い順
  - タグ: ゲストは並べ替えなし（実質 ID の順）→ 名前の順
- `app/items/new/page.tsx` を消す（提案。確認事項 2）。画面からの入り口がなく（プリキャッシュの一覧 `src/lib/sw/config.ts` にだけある）、商品の追加はホームの追加のシート（`ItemForm`）で行っている

## Capabilities

### New Capabilities

なし

### Modified Capabilities

- `catalog`: 「商品の一覧の絞り込み」と「タグの一覧」の並びを、モードによらずサーバーと同じにする

## 影響するモード

| モード | 影響 |
|-------|------|
| ゲスト | 商品とタグの並びが変わる。`/items/new` が開けなくなる（入り口はない） |
| サーバーファースト・ローカルファースト | 並びは変わらない。`/items/new` が開けなくなる |

## Non-goals

- サーバー（ログイン中）の並びを変えること
- 商品の追加の画面（`ItemForm`）の変更

## Impact

- 変更: `src/hooks/data/catalogQueries.ts`（`order` の分岐をなくす）、`src/lib/sw/config.ts`（プリキャッシュの一覧から `/items/new` を外す）
- 削除: `src/app/items/new/page.tsx`。`lib/db/items.ts` の `createItem`・`lib/db/tags.ts` の `createTag` がほかで使われていなければ消す
- E2E: ゲストの並びを前提にしたテストがあれば直す

## ユーザーに確認すること

specs と design は、各項目の「提案」で書いている。違う答えなら specs を直す。

1. **ゲストの一覧の並び**: 今は、ゲストとログイン中で並びが違う
   - 商品: ゲストは新しい順、ログイン中は古い順
   - タグ: ゲストは並べ替えなし、ログイン中は名前の順
   - そろえるか、そろえるならどちらに合わせるか
   - 提案: ログイン中（古い順・名前の順）に合わせる。主な利用者はログインして使っていて、その見え方を変えないため。ゲストの商品の並びは逆になる
2. **`app/items/new/page.tsx`（`/items/new`）の扱い**: 画面からの入り口がない古いページで、ログイン中でもゲスト DB に書いてしまう（作った商品がホームに出ない）
   - 案 a: ページを消す
   - 案 b: hooks 経由に直す（ログイン中はサーバーかユーザー DB に書くようになり、タグの選択肢は選んでいるグループのものだけになる）
   - 提案: 案 a（消す）。商品の追加はホームのシートでできるため
