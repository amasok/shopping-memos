# パフォーマンス・モデル選択

## モデル選択ガイド

| モデル | 用途 |
|--------|------|
| **Haiku** | 場所探し、ログ・ドキュメントの読み取り、コマンド1つで済む確認 |
| **Sonnet** | 定型的な実装、ドキュメント更新、テストの実行と修正 |
| **Opus** | 設計、セキュリティ、複雑なロジック、バグ調査、レビュー |

迷ったら上位のモデルを使う。手戻りのコストの方が高い。

## コンテキスト

- 大きいファイルは必要な範囲だけ読む。同じ調査を繰り返さない
- 大規模リファクタリングはコンテキストに余裕があるうちに始める

## 必須事項

- リストのクエリには LIMIT を付ける。N+1 を作らない
- 大きなコンポーネントは `next/dynamic` で遅延読み込みする
- ビルドエラーは1つずつ最小の変更で直す（`build-fix` スキル）

コード例は `performance-patterns` スキル、DB は `postgres-patterns` スキルを参照。
