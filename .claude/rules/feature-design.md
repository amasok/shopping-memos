# 機能設計

## 原則

**機能を実装する前に必ず設計書を作成し、ユーザーの承認を得てから実装に入ること。**

## 設計書の置き場所

```
docs/features/<機能名>.md
```

例:
- `docs/features/multi-select.md`
- `docs/features/sharing.md`

## 設計書のテンプレート

```markdown
# <機能名>

## 概要
[機能の目的・背景を1-3文で]

## ユーザーストーリー
- ユーザーとして、〜できる

## UIフロー
[画面遷移・操作フローをテキストで表現]

## 実装方針
- コンポーネント変更
- 状態管理
- データフロー

## 影響範囲
- 変更するファイル一覧

## 考慮事項
- エッジケース
- 既存機能への影響
```

## フロー

```
1. 設計書を docs/features/<機能名>.md に作成
2. ユーザーに設計書のレビューを依頼
3. 承認後に実装開始
4. 実装完了後、設計書に「実装済み」を記載
```

## やってはいけないこと

- ❌ 設計書なしで実装を開始する
- ❌ 設計書の承認前にコードを書く
- ❌ 設計書と異なる実装をする（変更時は設計書を先に更新）
