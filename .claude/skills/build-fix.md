# /build-fix - ビルドエラー修正

ビルドエラーを1つずつ安全に修正する。新しいエラーが発生したら即停止。

## コマンド

```
/build-fix           - ビルドエラーを順番に修正
/build-fix --dry-run - 修正内容をプレビュー（実行しない）
/build-fix --max=5   - 最大5件まで修正
```

## 修正ワークフロー

```
1. ビルド実行
   ↓
2. エラーをパース
   ↓
3. 重大度でソート
   ↓
4. 1件ずつ修正:
   a. コンテキスト表示
   b. 原因診断
   c. 修正実行
   d. 再ビルド
   e. 確認
   ↓
5. 完了 or 停止
```

## 停止条件

- ✅ 全エラー修正完了
- ⚠️ 修正でエラーが増加
- ⚠️ 同じエラーが3回連続で失敗
- ⚠️ ユーザーが停止を要求

## エラー分類

### 🔴 Critical (即修正)
- 構文エラー
- import/export エラー
- 型の根本的な不一致

### 🟡 High (優先修正)
- 型推論エラー
- null/undefined エラー
- プロパティ不存在

### 🟢 Medium (後で修正可)
- 非推奨API使用
- 未使用変数
- スタイルの問題

## 安全対策

### 修正前のバックアップ

```bash
# 自動でgit stashを作成
git stash push -m "build-fix-backup-$(date +%Y%m%d-%H%M%S)"
```

### ロールバック

```bash
# 修正を取り消す場合
git stash pop
```

## 最小差分の原則

**✅ やること:**
- 型注釈の追加
- import文の修正
- nullチェックの追加

**❌ やらないこと:**
- リファクタリング
- 変数名の変更
- ロジックの変更
- 「ついでに」の修正

---

**原則: 1つずつ、安全に、最小限の変更で。**
