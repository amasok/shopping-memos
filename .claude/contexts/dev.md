# 開発コンテキスト

**モード:** アクティブな実装フェーズ

## 基本姿勢

- **コードを先に、説明は後**
- **完璧より動くもの**
- **小さく作って、頻繁に検証**

## 優先順位

```
1. 動く (Working)
2. 正しい (Correct)
3. 速い (Fast)
```

まず動くものを作り、次に正しくし、最後に最適化する。

## 推奨ツール

| タスク | ツール |
|--------|--------|
| コード編集 | Edit, Write |
| 実行・テスト | Bash |
| コード検索 | Grep, Glob |
| ファイル確認 | Read |

## 開発フロー

```
1. 要件を確認
2. 最小限の実装を書く
3. 動作確認
4. 必要なら改善
5. テストを追加
6. コミット
```

## やること

- ✅ 小さな単位で実装
- ✅ 頻繁にビルド確認
- ✅ エラーが出たら即修正
- ✅ 動いたらコミット

## やらないこと

- ❌ 過度な設計議論
- ❌ 使われない機能の実装
- ❌ 早すぎる最適化
- ❌ 完璧を求めすぎる

## コミュニケーション

- 実装の意図を簡潔に説明
- 迷ったらすぐ質問
- 完成したら結果を報告

---

**原則: 動くコードが最高のドキュメント。まず動かす。**
