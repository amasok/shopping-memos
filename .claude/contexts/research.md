# 調査コンテキスト

**モード:** 探索・調査・学習フェーズ

## 基本姿勢

- **理解してから行動**
- **広く読んで、深く理解**
- **仮説を立てて検証**

## 優先順位

```
1. 理解する (Understand)
2. 仮説を立てる (Hypothesize)
3. 検証する (Verify)
4. 文書化する (Document)
```

実装は理解が十分になってから。

## 推奨ツール

| タスク | ツール |
|--------|--------|
| コード理解 | Read |
| パターン検索 | Grep, Glob |
| 外部情報 | WebFetch, WebSearch |
| 探索 | Task (Explore) |

## 調査フロー

```
1. 質問・課題を明確化
   「何を知りたいのか？」

2. 関連コード・ドキュメントを調査
   - 既存の実装を読む
   - 関連ファイルを探す
   - 外部ドキュメントを参照

3. 仮説を立てる
   「おそらく〇〇だろう」

4. 仮説を検証
   - コードを追う
   - 実際に動かして確認
   - ログを確認

5. 発見を整理・報告
   - 何がわかったか
   - 何がまだ不明か
   - 推奨アクション
```

## やること

- ✅ 既存コードを丁寧に読む
- ✅ 関連ファイルを広く探索
- ✅ 不明点をリストアップ
- ✅ 発見を文書化

## やらないこと

- ❌ 理解前にコードを書く
- ❌ 推測だけで判断
- ❌ 調査結果を記録せずに進む
- ❌ 重要な詳細を見落とす

## 出力フォーマット

```markdown
## 調査結果

### 質問
[調査した質問・課題]

### 発見
1. [発見1]
2. [発見2]

### 関連ファイル
- `src/path/to/file.ts` - [役割]
- `src/path/to/another.ts` - [役割]

### 未解決の疑問
- [まだわからないこと]

### 推奨アクション
- [次にすべきこと]
```

## コミュニケーション

- 発見したことを先に報告
- 推奨は発見の後に
- 不確実なことは明示

**原則: 理解なき実装は技術的負債。まず理解する。**
