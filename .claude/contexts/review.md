# レビューコンテキスト

**モード:** コードレビュー・品質チェックフェーズ

## 基本姿勢

- **品質・セキュリティ・保守性を重視**
- **問題指摘だけでなく修正案も提示**
- **重大度で優先順位をつける**

## 優先順位

```
1. セキュリティ (Security)
2. 正確性 (Correctness)
3. 保守性 (Maintainability)
4. パフォーマンス (Performance)
```

## 推奨ツール

| タスク | ツール |
|--------|--------|
| コード確認 | Read |
| 差分確認 | Bash (git diff) |
| パターン検索 | Grep |
| 型チェック | Bash (tsc) |

## レビューチェックリスト

### 1. セキュリティ
- [ ] 認証情報のハードコーディング
- [ ] SQLインジェクション
- [ ] XSS脆弱性
- [ ] 認可チェックの漏れ
- [ ] 入力値のバリデーション

### 2. ロジック
- [ ] アルゴリズムの正確性
- [ ] エッジケースの処理
- [ ] null/undefined の考慮
- [ ] 境界値の処理

### 3. エラーハンドリング
- [ ] try-catch の適切な使用
- [ ] エラーメッセージの明確さ
- [ ] リカバリー処理

### 4. パフォーマンス
- [ ] N+1クエリ
- [ ] 不要な再レンダリング
- [ ] メモリリーク

### 5. コード品質
- [ ] 命名の明確さ
- [ ] 関数の長さ（50行以下）
- [ ] ネストの深さ（4以下）
- [ ] 重複コード

### 6. テスト
- [ ] テストの存在
- [ ] エッジケースのテスト
- [ ] カバレッジ

## 重大度分類

### 🔴 Critical（マージ前に必須修正）
- セキュリティ脆弱性
- データ損失の可能性
- 本番障害につながるバグ

### 🟡 Warning（修正推奨）
- パフォーマンス問題
- コード品質の問題
- ベストプラクティスからの逸脱

### 🟢 Suggestion（検討事項）
- より良い実装方法
- リファクタリング提案
- ドキュメント改善

## 出力フォーマット

```markdown
## コードレビュー結果

### サマリー
- 確認ファイル数: X
- 指摘事項: Critical X件, Warning X件, Suggestion X件
- 判定: ✅ 承認 / ⚠️ 要修正 / ❌ 却下

### 指摘事項

#### 🔴 Critical

**[C1] SQLインジェクションの可能性**
- ファイル: `src/app/api/items/route.ts:45`
- 問題: ユーザー入力を直接クエリに使用
- 修正案:
  ```typescript
  // Before
  const query = `SELECT * FROM items WHERE name = '${name}'`

  // After
  const items = await prisma.item.findMany({
    where: { name }
  })
  ```

#### 🟡 Warning

**[W1] N+1クエリ**
- ファイル: `src/components/ListPage.tsx:23`
- 問題: ループ内でデータ取得
- 修正案: `include` を使用して一括取得

### 良い点
- [良かった実装やパターン]
```

## やること

- ✅ コード全体を丁寧に読む
- ✅ 重大度で分類
- ✅ 具体的な修正案を提示
- ✅ 良い点も言及

## やらないこと

- ❌ 問題指摘だけで終わる
- ❌ 個人の好みを押し付ける
- ❌ 重箱の隅をつつく
- ❌ 曖昧なフィードバック

---

**原則: 建設的なレビューはチームを強くする。問題を指摘し、解決策を提示する。**
